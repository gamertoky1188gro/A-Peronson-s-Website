### 2. Server-Side Memory Leak & Error-Handling Cleanup

#### `server/middleware/rateLimiter.js` — Full rewrite
- Restructured into a factory pattern: `createRateLimiter({ windowMs, max, store, prefix })`.
- **Memory store** (`createMemoryLimiter`): Renamed from the anonymous default, with lazy cleanup initialization (`ensureMemoryCleanup`) to avoid starting the interval timer before the limiter is first used.
- **Redis store** (`createRedisLimiter`): New implementation using `INCR` + `EXPIRE` via the Redis client. Falls back to memory limiter if Redis is disconnected.
- **Named limiters**: Pre-built instances exported — `authLimiter` (15 min, 20 max), `passkeyLimiter` (15 min, 10 max), `adminLimiter` (1 min, 60 max), `generalLimiter` (1 min, 100 max).

#### `server/middleware/adminSecurity.js` — Real IP/device checking
- `isAllowedIp()`: Was a no-op (`return true`). Now parses a comma-separated allowlist, supports CIDR notation (`192.168.1.0/24`), and checks against `req.ip`.
- `isAllowedDevice()`: Was a no-op (`return true`). Now checks `x-device-id` header (or `user-agent`) against a comma-separated allowlist.
- Removed unused `chalk` import.

#### `server/routes/adminRoutes.js`
- Added `router.use(adminLimiter)` — rate-limits all admin routes at 60 req/min.

#### `server/routes/authRoutes.js`
- Moved `authLimiter` and `passkeyLimiter` creation out of module scope into the centralized `rateLimiter.js` exports. Now imports pre-built instances.

#### `server/middleware/requestLogger.js`
- Added `req.destroy()` on 504 timeout to cleanly terminate hung requests.

#### `server/server.js` — `catch` error logging
- Two `.catch(() => {})` handlers (for uploadsService and aiModerationService imports) now log errors: `.catch(err => logError("...", err))`.

#### `server/services/*` — Silent catch fix
- **cmsService.js, infraService.js, networkService.js, securityService.js, serverAdminService.js**: All `.catch(() => {})` calls for `fs.mkdir`, `fs.writeFile`, and backup operations now log via `logError`.
- **messageService.js, productService.js, qdrantService.js, requirementService.js**: All `.catch(() => {})` on async operations (index, summarize) now log via `logError`. The `requirementService` and `productService` also removed the outer empty catch when calling `indexRequirementQdrant`/`indexProductQdrant` — the `.catch` is now explicitly paired with the async call.

#### `server/controllers/adminController.js`
- Added pagination (`skip`/`take`) to `verificationAudit`, `subscriptionsAudit`, and `usersAudit` — returning `{ data, total, skip, take }` instead of unbounded arrays.
- Fixed duplicate import: `logInfo`/`logError` imported twice (once from local, once from `../utils/logger.js`). Removed the redundant local import.
- The `usersAudit` handler now paginates before the `password_hash` redaction, improving memory usage for large user tables.

#### `server/utils/prisma.js` — Test-mode Proxy
- Replaced the empty-object `prisma = {}` fallback with a `Proxy` that intercepts model-name property access and returns mock CRUD methods (`findMany`, `findUnique`, `findFirst`, `count`, `create`, `update`, `delete`, `upsert`, `createMany`, `deleteMany`, `updateMany`, `aggregate`, `groupBy`), all resolving to empty/zero values. Prisma lifecycle methods (`$on`, `$connect`, `$disconnect`, `$use`, `$extends`, `$transaction`) return `undefined`. This prevents runtime crashes in unit tests that touch any model delegate without needing per-test stubs.

#### `server/utils/redis.js` — SCAN-based cache invalidation
- `cacheInvalidatePattern()`: Replaced `client.keys(pattern)` with cursor-based `SCAN` (MATCH + COUNT 100) to avoid blocking the Redis event loop on large key spaces.

### 4. Client Code Fixes

#### `src/components/FloatingAssistant.jsx`
- WebSocket cleanup: Added `onopen = null` and `onmessage = null` before close (previously only nullified `onclose` and `onerror`). Also checks for `CONNECTING` readyState in addition to `OPEN` when deciding whether to close — fixes a race condition where the socket is still connecting.

#### `src/components/ui/CyberpunkCursor.jsx`

#### `src/lib/auth.js`
- Added in-memory user cache with 60-second TTL (`cachedUser`, `cacheTime`, `CACHE_TTL_MS`). `fetchAndCacheUser` fetches the current user from API and caches it, reducing redundant API calls.

#### `src/lib/notificationsRealtime.js`
- WebSocket lifecycle rewrite: Event handlers are now stored in a `handlers` object and old handlers are removed via `removeEventListener` before closing the old socket and creating a new one. This prevents duplicate listeners accumulating across reconnects.

#### `src/lib/types.js`
- Added JSDoc type annotations for `profile` nested fields on `User`. Exported `User` and `AuthResponse` as concrete objects (previously `export {}`), enabling proper type imports.

## Why This Change Was Needed

This commit resolves 20 audit items (#31–#50) spanning multiple categories:

- **Dead code / maintainability (#31–#35)**: Huge single-file components (AdminPanel at 12k+ lines, ChatInterface at 1.5k+ lines, NavBar with 4 inline components) were impossible to maintain, test, and review.
- **Memory leaks (#36–#38)**: Silent `.catch(() => {})` swallows hid async errors. WebSocket listeners accumulated across reconnects. Event listeners on `.magnetic` elements leaked on every render. The Redis `KEYS` command blocks the event loop on large datasets.
- **Test pollution (#39–#42)**: Tests shared mutable `prisma` mock state without per-test cleanup. `NODE_ENV` leaked between test files. Cypress placeholder file was dead code. E2E test skips used verbose inline syntax.
- **Build config / deployment (#43–#46)**: Babel's ES module transform didn't adapt to test vs. production, causing Jest failures. Docker ran as root with no health check. `db:migrate:pg` used `migrate dev` (interactive) instead of `migrate deploy`. Render deployment ran migrations during build instead of as a release step.
- **Docker / infra (#47–#48)**: No `.dockerignore` bloated image context. No `.eslintignore` caused linting of generated files. docker-compose lacked OpenSearch for local search dev.
- **Env var restoration (#49–#50)**: Test script had hardcoded fallback credentials and command-exec allowlists — a security risk. Real IP and device allowlisting in admin security was completely disabled (no-op `return true`).

## Was It Useful

**Critical** — This commit fixes real security vulnerabilities (admin security no-op, hardcoded test credentials, Docker root), prevents production outages (silent catch swallows, Redis KEYS blocking), enables CI (test pollution, Babel config), and dramatically improves maintainability (monolith splitting).
