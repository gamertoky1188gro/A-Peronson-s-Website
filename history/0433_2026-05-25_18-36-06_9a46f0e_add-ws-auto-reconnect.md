## High-Level Summary
Replaces the single WebSocket connection with a persistent reconnect loop. On close/error, schedules a new connection attempt after 30 seconds. Retries indefinitely until component unmounts. Refactors WS URL generation into a standalone function and uses refs for the streaming IDs set and reconnect timer.

| File | Change |
|------|--------|
| `src/components/FloatingAssistant.jsx` | 55 insertions, 16 deletions |

## Detailed Diff Analysis
- `getWsUrl()` extracted as standalone function
- `connectWs()`: creates WS, sets up event handlers, schedules reconnect on close
- `scheduleReconnect()`: 30s `setTimeout` to call `connectWs()` again
- `cancelReconnect()`: clears the timeout
- Cleanup on unmount: cancels reconnect, clears event handlers, closes socket
- `streamingIds` moved to `streamingIdsRef` (useRef)

## Why This Change
The assistant WS could disconnect and never recover (e.g., server restart, network blip). Auto-reconnect makes it resilient.

## Was It Useful
Yes — essential for production reliability.

## Impact Analysis
**Medium.** Reliable WS connection is critical for real-time assistant chat. No limit on retries prevents permanent disconnection.

## Relationships
Part of the broader infrastructure reliability push (also 0434). Applied to FloatingAssistant specifically; 0434 applies similar pattern to other WS clients.

## Confidence Notes
High — standard reconnect pattern with proper cleanup.
