## Detailed Diff Analysis
**db.js:** New `startDbHeartbeat()` — every 30s runs `SELECT 1` via Prisma. If connection fails, marks `dbConnected = false` and logs. On success, reconnects.

**openSearchService.js:** New `startOpenSearchHeartbeat()` — every 30s pings OpenSearch. On failure, destroys the client object so next request recreates it.

**redis.js:** Changed reconnect strategy from exponential backoff (max 3 retries, cap 3s) to infinite retries at 30s intervals.

**notificationsRealtime.js:** Removed exponential backoff (`reconnectDelayMs`) — now uses constant 30s.

**CallInterface.jsx:** Adds 30s reconnect timer on WS close.

**ChatInterface.jsx:** Changed from 1.5s to 30s reconnect delay.

## Why This Change
In production, transient network issues or service restarts could permanently disconnect critical infrastructure. Exponential backoff was too aggressive and exhausted retries quickly. A steady 30s heartbeat keeps services connected.

## Was It Useful
Yes — systemic reliability improvement across all infrastructure layers.

## Impact Analysis
**High.** Affects every backend service and frontend WS connection. Eliminates most permanent-disconnect failure modes.
