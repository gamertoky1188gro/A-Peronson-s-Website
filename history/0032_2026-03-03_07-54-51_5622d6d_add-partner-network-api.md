## High-Level Summary

Introduces the full partner network system with backend CRUD APIs for partner requests (send, accept, reject, cancel) and a completely rewritten frontend page. The PartnerNetwork page now loads data from the API, supports status-based tabs, search filtering, and role-based action buttons.

## Detailed Diff Analysis

The backend enforces role-based access: only `buying_house` and `factory` roles can send/respond to requests (`agent` gets view-only). The service validates account existence, prevents self-requests, checks for duplicates, and enforces that partner relationships only form between factories and buying houses. The frontend now has three tabs (Connected, Pending, Rejected), a search box, and action buttons conditional on role permissions.

## Why This Change May Have Been Needed

The partner network was a static mock page. Real API support enabled users to form verified business connections between factories and buying houses, a core workflow requirement.

## Was It Useful?
