# 0432 — Fix session pre-load: fetch session data on mount, not just on panel open

## High-Level Summary
Splits session loading into two phases: (1) an immediate fetch on component mount (regardless of panel state) so data is ready when panel opens, and (2) a fallback fetch when the panel opens if the mount-load didn't execute (e.g., userId wasn't available). Uses a ref (`sessionLoadedRef`) to prevent duplicate fetches.

## Detailed Diff Analysis
- Mount effect: runs when `userId` changes, fetches session data unconditionally
- Panel-open effect: runs only if `sessionLoadedRef.current` is false
- Both populate `messages`, `title`, `hasUserMessagesRef`
- Default greeting message moved to the panel-open fallback path only
- Cleaner separation of concerns with ref-based dedup

## Why This Change
Previously, session data was only fetched when the panel opened, causing a visible loading delay. Pre-fetching on mount eliminates this delay.
